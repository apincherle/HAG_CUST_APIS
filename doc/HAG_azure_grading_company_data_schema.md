# Azure-First Data Schema for a Card Grading Company (SQL + Blob Storage)

This document defines a **production-ready relational data schema** for a grading company using a **full Azure stack**:

- **Azure SQL Database** for relational data (customers, submissions, cards, grading, audit, slab/QR)
- **Azure Blob Storage** for images and evidence assets
- **Azure Key Vault** for QR signing keys and secrets
- **Azure Functions / App Service** for ingestion, grading orchestration, verification endpoints
- **Azure Service Bus / Event Grid** (optional) for reliable async workflows

Images and derived assets live in Blob Storage and are **referenced from SQL** via `captures` and `evidence_assets` tables.

---

## 1) Design goals

1. **Consistency + auditability**: immutable original captures, hash-verified, with full grade history.
2. **Automation**: edge capture uploads instantly; metadata drives categorization (no folder naming by humans).
3. **Regrade-friendly**: every grading run is stored; the “current official” grade is a pointer.
4. **Anti-counterfeit slabs**: QR payload + signature validates authenticity and links to verify portal.

---

## 2) Azure storage strategy for images

### Blob Storage containers (recommended)
- `grading-raw` — RAW/DNG originals (immutability preferred)
- `grading-jpg` — normalized JPG previews (fast UI)
- `grading-evidence` — AI/human evidence assets (tiles, heatmaps, annotated views)
- `grading-exports` — customer packets, PDFs, shipping labels, etc.

### Blob path convention (human readable but not authoritative)
```
{container}/
  {submission_number}/
    {card_id}/
      captures/{capture_id}.{ext}
      evidence/{grading_run_id}/{asset_id}.{ext}
```

### Access
- Internal services: managed identity + RBAC
- UI: **time-limited SAS** URLs generated by backend
- Public verification: no direct blob access; serve via API/portal

## 3) SQL entity overview (ER map)

- `customers` 1→N `submissions`
- `submissions` 1→N `submission_items`
- `submission_items` 1→N `cards` (supports quantity > 1)
- `cards` 1→N `captures`
- `cards` 1→N `grading_runs`
- `grading_runs` 1→N `subscores`, 1→N `defects`, 1→N `evidence_assets`
- `cards` 0→1 `final_grades` (current official grade)
- `final_grades` 1→N `grade_audits`
- `cards` 0→1 `slabs` (serial + QR)

---

## 4) Canonical identifiers and conventions

### Primary keys
- Use **ULIDs** (string) or `uniqueidentifier` (GUID).  
  **Recommendation (Azure SQL):** `uniqueidentifier` with `NEWSEQUENTIALID()` for clustered PKs.

### Human-facing IDs
- `submission_number`: `SUB-YYYY-######` (unique)
- `slab_serial`: `GRA-YY-ABCDEFG` (unique)

### Immutable originals
- Original captures should never be overwritten.
- Store `sha256` in SQL and verify on upload.

## 5) Enums (reference)

You can implement as `VARCHAR` + check constraints, or lookup tables.

### Submission status
`CREATED | RECEIVED | IMAGING | GRADING | QA | SLABBED | SHIPPED | CLOSED | CANCELLED`

### Card state
`INTAKE | IMAGED | GRADED | SLABBED | ARCHIVED`

### Capture side
`FRONT | BACK`

### Light modes (Tier C baseline)
`DIFFUSE_XPOL | RAKE_TOP | RAKE_LEFT | RAKE_RIGHT | RAKE_REAR`

### Grading run type
`AI_PRE | HUMAN_REVIEW | QA_CHECK | REGRADE | AUTH_CHECK`

### Defect severity
`LOW | MED | HIGH`

### Slab status
`PRINTED | APPLIED | REPRINTED | VOID`

## 6) Azure SQL DDL (tables + keys + indexes)

> Note: This is a clean starting point. You’ll likely add columns for pricing, payments, shipping carriers, etc.

### 6.1 Customers

```sql
CREATE TABLE dbo.customers (
  customer_id UNIQUEIDENTIFIER NOT NULL DEFAULT NEWSEQUENTIALID(),
  email NVARCHAR(320) NOT NULL,
  phone NVARCHAR(50) NULL,
  full_name NVARCHAR(200) NOT NULL,
  billing_address_json NVARCHAR(MAX) NULL,
  shipping_address_json NVARCHAR(MAX) NULL,
  created_at DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
  CONSTRAINT PK_customers PRIMARY KEY CLUSTERED (customer_id),
  CONSTRAINT UQ_customers_email UNIQUE (email)
);
```

### 6.2 Submissions

```sql
CREATE TABLE dbo.submissions (
  submission_id UNIQUEIDENTIFIER NOT NULL DEFAULT NEWSEQUENTIALID(),
  customer_id UNIQUEIDENTIFIER NOT NULL,
  submission_number NVARCHAR(30) NOT NULL,
  status NVARCHAR(20) NOT NULL,
  service_level NVARCHAR(20) NOT NULL,
  declared_value_total DECIMAL(12,2) NULL,
  notes_internal NVARCHAR(MAX) NULL,

  created_at DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),
  received_at DATETIME2 NULL,
  imaging_started_at DATETIME2 NULL,
  grading_started_at DATETIME2 NULL,
  qa_at DATETIME2 NULL,
  slabbed_at DATETIME2 NULL,
  shipped_at DATETIME2 NULL,
  closed_at DATETIME2 NULL,

  CONSTRAINT PK_submissions PRIMARY KEY CLUSTERED (submission_id),
  CONSTRAINT UQ_submissions_number UNIQUE (submission_number),
  CONSTRAINT FK_submissions_customers FOREIGN KEY (customer_id)
    REFERENCES dbo.customers(customer_id)
);
CREATE INDEX IX_submissions_customer ON dbo.submissions(customer_id);
CREATE INDEX IX_submissions_status ON dbo.submissions(status);
```

### 6.3 Submission items (what customer declares)

### 6.4 Cards (canonical internal record per physical card)

```sql
CREATE TABLE dbo.cards (
  card_id UNIQUEIDENTIFIER NOT NULL DEFAULT NEWSEQUENTIALID(),
  submission_item_id UNIQUEIDENTIFIER NOT NULL,
  intake_barcode NVARCHAR(80) NOT NULL, -- unique physical intake ID
  game NVARCHAR(20) NOT NULL,

  -- normalized identification (may be filled after imaging/AI)

  variant NVARCHAR(120) NULL,

```

### 6.5 Captures (each image shot)

```sql
CREATE TABLE dbo.captures (
  capture_id UNIQUEIDENTIFIER NOT NULL DEFAULT NEWSEQUENTIALID(),
  card_id UNIQUEIDENTIFIER NOT NULL,
  side NVARCHAR(10) NOT NULL,         -- FRONT/BACK

  blob_path NVARCHAR(500) NOT NULL,   -- path inside container
  sha256 CHAR(64) NOT NULL,

  width_px INT NULL,
  height_px INT NULL,
  lane_id NVARCHAR(50) NULL,
  captured_at DATETIME2 NOT NULL DEFAULT SYSUTCDATETIME(),

  camera_body NVARCHAR(100) NULL,
  lens NVARCHAR(100) NULL,
  settings_json NVARCHAR(MAX) NULL,
  qc_flags_json NVARCHAR(MAX) NULL,

  CONSTRAINT PK_captures PRIMARY KEY CLUSTERED (capture_id),
  CONSTRAINT FK_captures_cards FOREIGN KEY (card_id)
    REFERENCES dbo.cards(card_id)
);
CREATE INDEX IX_captures_card ON dbo.captures(card_id);
CREATE INDEX IX_captures_card_side_mode ON dbo.captures(card_id, side, light_mode);

```

## 7) QR code payload and verification (v1)

### 7.1 Recommended QR content (small and robust)
Encode a short URL to your verification portal:

```
https://verify.yourdomain.com/{slab_serial}?sig={signature}
```

### 7.2 What gets signed
Sign a canonical string (deterministic formatting):

```
v=1|serial=GRA-25-ABCDEFG|grade=9.50|policy=policy_v1.2.0|date=2025-12-23
```

### 7.3 Signature scheme (recommended)
- **Ed25519** keypair in **Azure Key Vault**
- Sign in backend when creating the slab record
- Verify signature on every verify request

Store in SQL:
- `slabs.qr_payload_json` (full details, versioned)
- `slabs.qr_signature` (base64url)

### 7.4 Example payload stored in `slabs.qr_payload_json`
```json
{
  "v": 1,
  "issuer": "YOURCO",
  "slab_serial": "GRA-25-ABCDEFG",
  "card_id": "e7c4d5a5-....",
  "grade": 9.5,
  "subscores": {
    "centering": 9.5,
    "corners": 9.0,
    "edges": 9.5,
    "surface": 9.0
  },
  "policy_version": "policy_v1.2.0",
  "finalized_at": "2025-12-23T10:15:00Z",
  "verify_url": "https://verify.yourdomain.com/GRA-25-ABCDEFG"
}
```

## 8) Event-driven workflow (Azure)

### Edge capture → Azure
1. Edge agent uploads RAW/JPG to Blob Storage
2. Edge agent inserts `captures` row in Azure SQL
3. Emit event: `capture.created` via Service Bus/Event Grid

### Grading orchestration
1. Grading orchestrator creates `grading_runs`
2. AI services produce `subscores`, `defects`, `evidence_assets`
3. Human approval sets/updates `final_grades`
4. Slabbing generates `slabs` + QR signature

---

## 9) Implementation checklist
- Use `NEWSEQUENTIALID()` for clustered PKs to reduce fragmentation.
- Make RAW blobs immutable (Blob immutability policy) where possible.
- Always store hashes and verify after upload.
- Generate SAS URLs server-side only; never store SAS in DB.
- Version grade policies and QR payloads from day 1.
